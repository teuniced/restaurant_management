Restaurant Management System: A Comprehensive Java Application

This project implements a restaurant management system using Java, incorporating  OOP principles, SOLID design principles, and functional programming concepts. 
This program is designed to handle multiple aspects of restaurant operations, including menu management, order processing, customer management, and recipe access control.

Here are Its Key Components and Their respective Implementations:
ManagementMain Class:
This is the central control unit of the program. ManagementMain drives the entire system. 
It utilizes composition by incorporating instances of Menu, CustomerManager, OrderManager, RecipeBook, and Authentication classes. 
The class implements a menu-driven interface, allowing users to navigate through different functionalities. 
It demonstrates the Single Responsibility Principle by delegating specific tasks to appropriate classes.


Authentication System:
The Authentication class manages user access, implementing a basic login system with different access levels. 
It stores user credentials and roles, show-casing encapsulation by keeping this sensitive information private. The system differentiates between staff and management access, particularly for sensitive areas like recipe access.

Menu Management:
The Menu class handles the restaurant's menu items. It uses a Map<String, List<String>> to store menu items, demonstrating efficient data structure usage. 
The class implements methods for viewing the full week's menu, daily menus, and special menus, show-casing the use of Java streams and functional programming for data filtering and processing.

Customer Management:
CustomerManager class manages customer data, using a Map for efficient customer lookup. 
It implements methods for adding new customers, viewing all customers, and retrieving customer information. 
The class demonstrates file I/O operations for persistent storage of customer data.

Order Processing:
OrderManager class handles order-related operations. It uses composition by containing a list of Order objects and a reference to CustomerManager.
The class show-cases file I/O for order persistence and implements methods for creating new orders and viewing all orders.

Recipe Book:
The RecipeBook class manages recipes with access control. 
It has file I/O by reading recipes from a text file and implements access control checks before displaying recipes, which is also an integration with the Authentication system.

Order and Customer Classes:
These classes serve as data models, demonstrating good encapsulation practices with private fields and public getters. The Order class showcases the use of Java 8's LocalDateTime for timestamp handling.

Design Principles and Programming Concepts:
SOLID Principles:
Single Responsibility: Each class has a well-defined purpose.
Dependency Inversion: The ManagementMain class could be improved by depending on abstractions rather than concrete implementations.


Object-Oriented Programming:
Encapsulation: Private fields with public methods for controlled access.
Composition: Extensive use of object composition for system integration.
Inheritance: While not heavily used, the system is structured to allow for inheritance if needed for future extensions.


Functional Programming:
Use of lambda expressions, particularly in the Menu class for filtering and processing menu items.

Error Handling and Tests:
Implementation of try-catch blocks for file I/O operations and user input validation.
Implementation of  3 JUnit tests to check for ensure menu management doesn't throw exceptions, 
	check if the authentication process doesn't throw exceptions and check if the recipe file exists and is not empty.


User Interface:
Implementation of a text-based, interface for user interaction.


Code Organization:
Clear separation of concerns across different classes.
Use of meaningful naming conventions for classes, methods, and variables.
Inclusion of comments for code clarity and maintainability.


Areas for Potential Improvement:
This program could benefit from the implementation of interfaces for major components to enhance abstraction and testability. 
Implementation of unit tests to ensure reliability of individual components.
